# Naming: OpenChart, PDRE and CareCircle Link

Three names, three jobs.

| Name | What it is | Who uses it | How to say it |
|---|---|---|---|
| **OpenChart** | The open-source project: this repo, the website, the community and the "OpenChart Certified" badge | Everyone | "OpenChart, powered by the PDRE protocol" |
| **PDRE** (Patient-Directed Record Exchange) | The technical protocol specification inside OpenChart: messages, FHIR profiles, consent, trust and conformance rules | Developers, vendors, standards bodies | "Our PMS implements PDRE 0.1" |
| **CareCircle Link** | CareCircle Connect Inc.'s own hosted network and apps built on OpenChart | CareCircle customers | "CareCircle Link, built on OpenChart" |

## How they fit together

- **OpenChart** is the brand people remember. It's what you search for, star on GitHub and see on a badge.
- **PDRE** is what engineers build to. Keeping a plain, descriptive protocol name makes it easy for vendors, governments and standards bodies to adopt and reference, and easy to hand to a neutral body later.
- **CareCircle Link** is not a fork. It runs the same open protocol as everyone else, with no private APIs or shortcuts. It is one hub operator on OpenChart, and other companies can run their own hubs and build their own apps on equal terms.

Think of it like a web browser and the web: anyone can build a browser to the open standards, and every browser works with every website.

## Writing rules

- Write **OpenChart** as one word, capital O and capital C.
- Write **PDRE** in capitals; spell out "Patient-Directed Record Exchange" on first use.
- Write **CareCircle Link** in full; don't shorten it.
- Say "implements PDRE" or "works with OpenChart" only when it's true. "OpenChart Certified" is only for products that pass certification (the programme isn't open yet).
